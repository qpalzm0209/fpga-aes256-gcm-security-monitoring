## 부팅

- RX: cable `210351BE7D5BA`, UART `D2XX:210351BE7D5BB`
- TX: cable `210351BD73BCA`, UART `COM4`
- 양쪽 결과: `SPACE=1 BOOTARGS=1 BOOTM=1 LOGIN=1 READY=1 SSH_KEY=SKIPPED`
- Vitis/XSDB 2025.2로 새 bit, FSBL, U-Boot, DTB와 새 `image.ub`를 직접 적재했다.

현재 보드 boot mode가 JTAG이므로 BootROM이 `BOOT.BIN` 컨테이너 자체를 읽는 SD 부팅은 수행하지 않았다. 대신 JTAG에서 `BOOT.BIN`을 구성하는 동일한 새 bit/FSBL/U-Boot/DTB와 `image.ub`를 실제 실행했고, `BOOT.BIN`은 Bootgen 4-image/DTB 주소와 SD 복사본 hash까지 검증했다. BootROM의 `BOOT.BIN` 소비를 별도로 확인하려면 물리 boot-mode jumper를 SD로 바꿔야 한다.

## Jetson 없는 자동 Secure Session

Jetson management 명령과 attack injector를 연결하지 않은 상태에서 다음 순서가 자동으로 확인됐다.

1. TX/RX WPA 상태 `COMPLETED`
2. TX `waiting for RX discovery on wlx705dccf1e097`
3. TX `TX creating default Secure Session without Jetson control`
4. TX/RX session `872c2e44`, counter `1` 커밋·확인
5. 양쪽 `key_valid=1`, `key_ready=1`, `busy=0`, `error=0`
6. `commit_pending=0`, `clear_pending=0`, `terminate_active=0`, `termination_count=0`
7. TX/RX session agent와 video service 모두 `running`

실기 N150UA 주소는 TX `70:5d:cc:f1:e0:97`, RX `70:5d:cc:f1:e3:57`이다. 기본 경로는 RX UDP announcement의 DHCP source IP를 사용하는 discovery이고, 고정 `AES_SESSION_PEER`는 명시 override일 때만 사용한다. health 검사는 10초 간격이며 첫 불건전 sample에서 repair한다.

## AES-GCM 및 600-frame 성능

- TX SW3: `switch=1`
- TX 로그: `mode=AES-GCM`
- Attack OFF: Jetson management/attack injection을 사용하지 않은 정상 경로
- 측정 시작: `processed=5700`, uptime `442.51 s`
- 측정 종료: `processed=6300`, uptime `462.56 s`
- 정확한 구간: `600 frames / 20.05 s = 29.925 fps`
- target `>=29.5 fps`: PASS
- hard gate `>=29.0 fps`: PASS

시작과 종료의 RX 누적값은 모두 다음과 같았다.

```text
auth_fail=0 replay_reject=0 status_fail=0
queue_overrun=0 stale=0 lost total=0
```

따라서 600-frame 구간에서 누적 packet/frame loss, 인증 실패, replay reject, DMA/status 실패, queue overrun 또는 stale drop 증가는 없었다. 1초 rolling `STATS`는 UART로 대량 로그를 수집하거나 10초 health 검사를 실행한 순간 짧게 흔들릴 수 있으므로, acceptance FPS는 PIPE 로그 경계 사이의 정확한 600-frame monotonic 구간으로 판정했다.

## BTN3 제거

TX production wrapper는 `ENABLE_TERMINATE_BUTTON=0`으로 구현하고 새 bitstream을 생성했다. BTN3 입력은 보드 제약에는 남아 있지만 배포 회로에서 session/key control에 사용되지 않는다. 최종 Vivado 2025.2 XSim 결과는 다음과 같다.

```text
PASS: core interlocks plus production wrapper BTN3-inert/AXI-CLEAR policy
PASS: frame-lock COMMIT/BTN3 interlock, generation-safe release request, SW2 one-shot and RX controls disabled
```

TX test는 BTN3 high/low에서 active key, active session, valid, request/termination count, pending 상태가 모두 불변이고 AXI `COMMAND_CLEAR`만 실제 clear를 수행함을 확인했다.
